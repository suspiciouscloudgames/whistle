# 인원에 반응하는 멀티플레이 사운드 패치

사운드 디자인 원본은 **`patches/multiplayer-interaction.pd`**다.
화음 구성, 음높이, 리듬과 전환 시간은 이 패치에서 수정한다.
TypeScript는 현재 상호작용 상태를 전달하고 세션의 시작·종료만 관리한다.

## 첫 테스트 디자인

인원수는 **나를 포함한 활성 3D 플레이어**다. 2D 편집자, 자리 비움, 퇴장,
서버에서 위치가 만료된 상대는 제외한다. 로컬 백그라운드 테스트를 켜 둔 3D 창은 포함한다.

| 활성 3D 인원 | 내 상호작용 소리 |
| --- | --- |
| 1명 | 220Hz 사인파 단음 |
| 2명 | 220 + 330Hz, 완전5도에 해당하는 두 음 |
| 3명 | 220 + 275 + 330Hz, 순정률 장3화음 |
| 4명 이상 | 220 + 275 + 330 + 440Hz, 옥타브가 추가된 리듬 화음 |

4명 모드에서는 가까운 상대가 멀수록 초당 2회, 가까울수록 초당 6회로 부드럽게 맥동한다.
최소 진폭은 최대의 15%다. 가장 가까운 상대의 거리로 계산하므로 같은 방에서도 각자가 듣는
리듬 속도는 달라질 수 있다. 1~3명에서는 연속 화음이며 거리에 의한 리듬 변화는 없다.
5~8명은 현재 4명 모드를 사용한다. 리듬 위상은 청취자별로 실행하며 전역 박자 동기화는 하지 않는다.

화음과 리듬의 변화가 테스트 대상이다. 음 수로 나누는 출력 정규화와 기존 원격 소리의
인원별 음량 보정은 혼합 레벨 관리용으로 별개다.
패치의 원본 출력 레벨은 0.035, 화음·리듬 파라미터 전환은 120ms다.

## 기존 소리와의 관계

- 방에서 혼자 3D에 들어간 때부터 개인별 패치 하나를 실행한다. 같은 세션에 상태를 갱신하며 인원이 바뀔 때 재시작하지 않는다.
- 패치가 준비되면 기존 **자기 플레이어의 지속 시험음**을 대신한다. 기존 편집음과 규칙 이벤트 소리는 그대로 사용한다.
- `remote-player.pd`의 상대별 위치·재질 소리는 계속 HRTF 공간음향으로 들린다.
  새 상호작용 패치는 청취자 중심 스테레오 출력이며 별도의 상대 아바타를 생성하지 않는다.
- UI의 ‘다른 사람의 소리’ 슬라이더는 기존 원격 위치음에만 적용한다. 새 패치의 화음·리듬 선택과는 독립적이다.
- 방 연결이 없는 혼자 플레이는 기존 소리를 사용한다. 새 패치 로딩에 실패해도 기존 자신의 지속음이 남으며 재시도한다.
- 내 2D 복귀·일시정지·퇴장 시 상호작용 패치를 정리한다. 상대의 2D 복귀·자리 비움·퇴장 시 남은 인원에 맞춰 변한다.

## 패치 입출력 계약

| 버스 | 방향 / 값 | 의미 |
| --- | --- | --- |
| `whistle-interaction` | JS → Pd `[players, proximity]` | 실제 활성 인원 1~8, 가장 가까운 상대의 근접도 0~1 |
| `whistle-gate` | JS → Pd `[0 또는 1]` | 이 패치의 음소거 / 재생 |
| `whistle-ready` | Pd → JS `bang` | DSP 준비 완료 |
| `dac~ 1 2` | Pd → Web Audio | 청취자 중심의 좌우 출력 |

근접도는 `max(0, 1 - 가장 가까운 상대 거리 / 8)`이다.
X/Z는 격자 단위이고 높이 차이는 장면 단위를 2로 나눈 뒤 3차원 거리에 합산한다.
상대가 없거나 8칸 이상 떨어져 있으면 0, 같은 위치면 1이다.
인원수는 거리와 무관하게 계산한다. Pd는 인원수를 1~4로 제한해 네 가지 디자인을 선택한다.

외부 입력용 최상위 `[s whistle-interaction]`, `[s whistle-gate]`와 각각의 `[r]`,
`[loadbang] → [s whistle-ready]` 및 `[r whistle-ready]`는 유지한다.
이름과 값의 순서를 유지하면 내부 합성 그래프를 교체해도 앱 코드를 바꿀 필요가 없다.
WebPd가 지원하는 오브젝트로 작성해야 하며 현재 패치는 기본 산술·osc~·line~ 객체로 구성했다.

## 수정 후 적용

```sh
npm run audio:build
# 실행 중인 각 테스트 창을 새로고침한 뒤 다시 플레이
```

생성 파일은 `public/audio-test/multiplayer-interaction/{patch.wasm,io.json}`이다.
생성된 WASM 대신 원본 `.pd`를 수정한다. `npm run dev`와 `npm run build`도 자동 컴파일한다.
`npm start`로 빌드 결과를 보고 있다면 `npm run build` 후 각 창을 새로고침한다.

## 확인 방법

같은 방을 네 창에 열고 각 창의 로컬 백그라운드 테스트를 켠다.
한 창씩 3D에 진입해 1→2→3→4명 상태를 만든다. 상단 ‘상호작용 소리’ 표시와 화음 변화를 확인한다.
4명 상태에서 한 사람이 다른 세 사람으로부터 멀어지면 그 사람의 리듬은 느려지고,
서로 가까이 남아 있는 세 사람의 리듬은 빠르게 유지된다.
2D 복귀·퇴장·자리 비움으로 4→3→2→1명 전환도 확인한다.

자동 검증은 인원 판정·개인별 근접도 및 기존 지속음 전환 단위 테스트와 기존 Pd 회귀 테스트를 포함한다.
별도로 실제 네 브라우저 컨텍스트를 접속시켜 패치의 출력 스펙트럼에서 220/330/275/440Hz 성분이
인원수에 따라 추가되는지 검사한다. 단순한 UI 표시나 입력값 변경만으로 성공을 판정하지 않는다.

2026-11-16 검증: 단위·서버 테스트 102개, 기존 오디오 브라우저 회귀 테스트 7개 및 빌드 통과.
네 접속 창의 실제 출력에서 각 화음 성분을 확인했다. 4명 모드의 측정 리듬은 근접도 1에서
6Hz, 근접도 0에서 2Hz였다. 2D 접속자는 인원수를 바꾸지 않았고, 2D 복귀·연결 종료·자리 비움으로
4→3→2→1 전환을 확인했다. 인원 변화 중 상호작용 패치와 AudioContext는 각각 하나로 유지됐다.
