# main.pd: 장면은 Pd가, 공간화·리미터는 JS가

장면 전체(영역 패치를 띄우고 지우기, 상호작용 패치, 패치끼리 엮기)를 Pd 패치 하나 `audio/patches/main.pd`에서 관리한다.
JS는 어느 영역이 켜지고 꺼지는지 메시지로 알리고, 나온 소리를 공간화하고 리미터를 건다.

## 왜 이렇게 나눴나

- 공간화(방향·거리)와 리미터는 Web Audio(JS)가 이미 잘 하고, Pd로 옮기기에는 자신이 없다. 그래서 그대로 JS에 둔다.
- 전에는 영역 패치의 동적 패칭도 JS가 했다(엔진의 빈 `index.pd`에 `[pd slotN]`을 만들고 채움). 그러면 패치들이 서로 고립되고,
  장면 전체를 Pd에서 마음대로 다루기 어렵다. 그래서 장면은 Pd 패치 하나로 모으고, JS는 켜기·끄기 메시지만 보낸다.

| | Pd (`main.pd`) | JS |
| --- | --- | --- |
| 장면 | 영역 패치를 띄우고 지운다(동적 패칭). 상호작용 패치, 공용 효과, 패치끼리 엮기 | 시작할 때 `main.pd`를 연다 |
| 영역 켜기/끄기 | `whistle-slot`을 받아 만들고 지운다 | 어느 영역이 가까운지 계산해 보낸다. 끌 때는 페이드 아웃이 끝난 뒤 보낸다 |
| 영역 값 | `[r $1-whistle-region]`으로 받는다 | `amount`, `distance`를 보낸다 |
| 출력 | 약속한 `dac~` 채널로 낸다 | 1–2는 그대로, 3–32는 쌍마다 공간화. 합쳐서 리미터 |
| 영역별 볼륨·페이드·방향 | 하지 않는다 | gain, panner, dry/wet([`slots-and-mix.md`](slots-and-mix.md)) |
| 상호작용 | `edit`·`player`·`event`를 두고 `dac~ 1 2`로 | 전역 버스로 보낸다(`whistle-player` 등). 음소거는 1–2 게인 |

## 채널

엔진 출력은 32채널(Web Audio 노드 출력의 최대)이다.

- **1–2: 믹스다운.** 공간화 없이 그대로 나간다. 상호작용 패치, 장면 전체의 리버브 같은 방향 없는 소리.
  보통의 Pd처럼 `[dac~]`(= `[dac~ 1 2]`)로 보내면 된다. 여러 패치가 보내면 Pd 안에서 더해진다.
- **3–32: 공간화.** 스테레오 15쌍 = 영역 15개까지 동시에. 슬롯 N(0–14)은 `dac~ 2N+3 2N+4`. JS가 쌍마다 panner를 붙인다.
- 마지막에 JS가 둘을 합쳐 리미터를 건다.

**스테레오로 둔 이유.** 패너(equalpower)는 스테레오 입력을 받으면 폭을 조금 살린 채 방향을 옮기지만, 옆으로 갈수록 모노처럼 접힌다
(멀리서 한 점으로 오는 소리는 원래 모노에 가깝다). 그래서 패너를 거치는 쪽에서는 스테레오 의미가 작다.
반면 영역 안에 서 있을 때의 소리(wet, 패너를 거치지 않음)는 패치의 스테레오가 그대로 나간다. 패치가 만든 좌우 차이가 살아 있는 곳이 여기다.
모노로 바꾸면 영역을 30개까지 띄울 수 있지만 이 좌우 차이를 잃는다. 15개로 충분하므로 스테레오로 둔다.

## 슬롯 = 지우기 위한 그릇

- vanilla Pd에는 "상자 하나만 지워라"는 간단한 메시지가 없다. 반면 `clear`는 캔버스 하나를 통째로 비운다.
  또 `connect`는 캔버스 안의 상자 번호(만든 순서)로 잇기 때문에, 한 캔버스에서 만들고 지우기를 반복하면 번호를 따라가기 어렵다.
- 그래서 띄울 것마다 그릇(서브패치)을 하나 두고, 그 안에서는 늘 0번(패치), 1번(`dac~`)으로 만들고 잇고, 지울 때는 `clear` 한 번.
  그릇 자체를 지우는 것도 같은 문제라 그릇은 늘 두고 돌려 쓴다.
- 그릇은 채널 자리와 하나씩 맞춘다: `main.pd`에 `[pd slot0]` … `[pd slot14]`.
- `dac~`는 그릇 안에서 패치와 함께 만들어지고 `clear` 때 함께 지워진다. `dac~`는 출력 채널에 더해 넣는 입구일 뿐이라
  상태가 없고, 같은 채널에 여러 개 있어도 더해진다. 그릇 밖에 고정하려면 `throw~`/`catch~`가 필요한데 그것도 그릇 안에서
  매번 만들어야 하므로 얻는 것이 없다.

## 이름(`$1`)은 그릇과 따로

- `[environment_water v17]`의 `v17`은 생성 인자일 뿐이다. 그 안의 `$1`이 모두 `v17`로 바뀐다:
  `[r $1-whistle-region]` → `[r v17-whistle-region]`. 같은 패치가 여러 영역에 동시에 떠도 서로 섞이지 않는다.
- `$1`과 `dac~` 번호는 아무 관계가 없다. 둘 다 메시지로 받아 적는다.
- 이름은 띄울 때마다 새것(`v1`, `v2`, …, 계속 늘어남)이다. 그릇은 돌려 쓰지만 이름은 다시 쓰지 않으므로, 꺼진 패치 앞으로
  늦게 온 메시지가 같은 그릇에 새로 뜬 다른 패치에 닿지 않는다. (Pd는 한 번 쓴 이름을 지우지 않지만 하나에 수십 바이트라 무시해도 된다.)

## 메시지 (JS → `main.pd`)

| 버스 | 메시지 | 뜻 |
| --- | --- | --- |
| `whistle-slot` | `on 번호 패치 이름 L R` | 예: `on 3 environment_water v17 9 10` → `[pd slot3]` 안에 `[environment_water v17] → [dac~ 9 10]` |
| `whistle-slot` | `off 번호` | 예: `off 3` → `[pd slot3]`을 비운다 |
| `<이름>-whistle-region` | `amount 0~1`, `distance 타일` | 영역 값(지금과 같음, [`pd-receive.md`](pd-receive.md)) |
| `whistle-player`, `whistle-edit`, `whistle-event`, `whistle-board-height` | (지금과 같음) | 상호작용 값([`pd-receive.md`](pd-receive.md)) |
| `whistle-player-stop` | `bang` | 3D 이동음을 끈다. 다음 `whistle-player` 메시지부터 다시 소리를 내는 것은 패치가 한다 |

- `on`은 같은 번호로 다시 와도 된다(먼저 비우고 다시 만든다). 개발 서버의 패치 갱신이 이것을 쓴다.
- 엔진이 열리면 JS가 `main.pd`를 바로 연다(pd4web `openPatch`. 일반 Pd에서 파일을 연 것과 같고 loadbang도 온다).

## `main.pd` 예시(최소)

```
[r whistle-slot]
|
[route on off]
|            \
[; pd-slot$1 clear, obj 20 20 $2 $3, obj 20 80 dac~ $4 $5, connect 0 0 1 0, connect 0 1 1 1, loadbang(
              [; pd-slot$1 clear(

[pd slot0] [pd slot1] … [pd slot14]

[edit] [player] [event]
 \  \    |  |    /  /
   [dac~ 1 2]
```

- `on 3 environment_water v17 9 10`이 `[route on off]`를 지나면 `3 environment_water v17 9 10`. 메시지 상자에서
  `$1` = 3(그릇 `pd-slot3`), `$2` = 패치, `$3` = 이름, `$4 $5` = 채널.
- `loadbang`을 빠뜨리지 않는다(동적으로 만든 패치에는 loadbang이 저절로 오지 않는다).

## 개발 서버의 패치 갱신

- 영역 패치(와 그 안의 abstraction)를 고치면 그것을 쓰는 슬롯에 `on`을 다시 보내고, 그 슬롯에 마지막으로 보낸 값을 다시 보낸다.
- `main.pd`(와 그 안의 패치: `edit`·`player`·`event` 등)를 고치면 `main.pd`를 닫고 다시 열고, 떠 있는 슬롯에 모두 `on`을 다시 보내고,
  전역 버스와 슬롯에 마지막으로 보낸 값을 다시 보낸다.
