# WebPd 오디오 설계와 최소 테스트

## 역할 분리

게임은 상호작용과 공간 상태를 계산하고 Pd에 전달한다. Pd는 그 값으로
합성·재생·엔벌로프·음색 변화를 처리한다. 오디오 때문에 지형을 다시 생성하거나
플레이어 이동 계산을 변경하지 않는다.

```text
2D 편집 결과 ── 단발 이벤트 ─┐
                            ├─ 오디오 어댑터 → WebPd AudioWorklet → Pd DSP → 출력
3D 이동 상태 ── 연속 값 ─────┘
```

하나의 AudioContext와 오디오 세션을 사용하고, 패치 안에서 편집용 소리와
플레이용 소리를 나눈다. 최종 패치가 여러 파일이면 상위 패치에서 합성한다.
현재 테스트는 단일 .pd 파일이다. 샘플 파일·외부 오브젝트·서브패치는 아직 검증하지 않았다.

## 현재 코드에서 연결할 곳

| 대상 | 현재 상태 | 실제 연결 시 처리 |
| --- | --- | --- |
| 2D 편집 | `app/page.tsx`의 `paint`, `clickedCell`과 `useWorldDocument`가 변경 처리 | 성공한 클릭/드래그의 변경 셀을 이벤트로 전송. 무변경 칠하기·초기 로드·자동 저장을 클릭 이벤트로 취급하지 않음 |
| 겹침/환경 | `placementChanges`와 `WorldDerivation`에 전후 환경 변화 정보가 있음 | 기존 캐시의 구조·환경을 이용해 아이콘 ID, 셀, 추가/삭제, 겹침/조합 결과를 구성. 오디오에서 환경 재계산 금지 |
| 3D 위치 | `Scene.onPlayer`가 약 80ms 간격으로 X/Z, yaw, pitch, falling 전달 | 연속 파라미터 전송에 재사용 가능. 순간적인 발걸음·착지 이벤트는 별도로 발생 시점에 전달 |
| 이동/접지 | 속도, 발 위치, 점프·접지는 `Scene` 내부에 있음 | 계산된 결과를 읽는 오디오용 콜백 추가. 카메라 흔들림 좌표 대신 발 위치 사용 |
| 풀/바위 | `environmentAt`의 grass, `terrainSample`의 rough 가중치 활용 가능 | 접지 여부와 함께 전달. rough는 바위 지면의 연속 가중치이며 개별 바위 오브젝트 접촉과는 별도 |
| 기존 소리 | `app/page.tsx`의 `initAudio`/`sound`가 직접 오실레이터 생성 | 실제 연결 단계에서 동일 이벤트를 Pd로 옮기고 중복 재생 제거 |

현재 편집기는 같은 셀의 아이콘 클릭을 삭제로 처리하는 경우가 있으므로,
‘겹침’을 동일 셀의 오브젝트 개수로만 정의하면 안 된다. 아이콘과 지형의 조합,
주변 아이콘으로 생기는 환경 변화 등을 구분하는 것이 필요하다.
이번 테스트의 `overlap`은 전달 경로를 확인하기 위한 0–1 입력값이다.

최종 메시지는 다음 두 계열로 나누는 것을 권장한다.

- 편집 이벤트: 이벤트 번호, 셀 X/Z, 아이콘 종류, 추가/삭제/조합 결과, 강도.
  한 드래그의 누적 셀 목록 전체를 매번 재전송하지 않고 새로 변경된 셀만 보낸다.
- 플레이 상태: 발 X/Y/Z, 방향, 수평 속도, 접지/점프/낙하, 풀·바위·물 등의 가중치.
  연속 값은 일정 주기로 보내고 Pd의 `line~` 등으로 보간한다. 정지 시 속도 0을 반드시 보낸다.
  순간 이벤트는 별도 번호를 붙여 같은 값의 반복과 구분한다.

좌표는 어댑터에서 변환한다. 격자 좌표와 3D 장면 좌표의 배율을 혼용하지 않는다.
월드 범위 정규화는 `(gridCoordinate + 0.5) / world.size`로 통일할 수 있다.
높이는 카메라 높이가 아닌 발 높이, 속도는 초당 격자 단위 등으로 단위를 고정해야 한다.
리스폰·텔레포트·문서 교체는 이동량 누적을 초기화해 큰 속도값이 생기지 않게 한다.
이 규칙은 설계안이며 아직 게임에 연결하지 않았다.

## 최소 테스트 구현

- 원본: `audio/patches/interaction-test.pd`
- WebPd: `1.0.0-alpha.14` 고정, 개발 의존성. `.pd`를 WASM으로 사전 컴파일한다.
- 브리지: `lib/audio/webpd-session.ts`
- 수동 테스트: `audio-lab/index.html`
- 브라우저 회귀 테스트: `tests/browser/audio.spec.ts`

| Pd 버스 | 입력 | 테스트 패치의 반응 |
| --- | --- | --- |
| `whistle-edit` | `[x, z, overlap]` | `440 + 220 × overlap` Hz, 짧은 엔벌로프. X/Z는 수신 확인용 |
| `whistle-player` | `[x, y, z, speed, grass, rough]` | `220 + 220z + 220grass + 440rough` Hz, 속도에 비례한 크기, X에 따른 좌우 출력. Y는 수신 확인용 |
| `whistle-gate` | `[0 또는 1]` | 전체 음소거/해제, 20ms 변화 |
| `whistle-ready` | 패치 → 브라우저 `bang` | DSP 초기화 확인 |

X/Z·겹침·풀·바위 값은 0–1, 테스트 속도는 0–4로 제한한다.
유한하지 않은 숫자는 전송하지 않는다. 테스트 음은 최종 사운드 디자인이 아니며,
X에 따른 좌우 출력도 실제 플레이어 방향을 고려한 3D 공간음향은 아니다.

WebPd alpha.14의 기본 외부 입력은 최상위 `[send]` 객체의 inlet으로 전달된다.
패치에 같은 이름의 `[s whistle-player]`와 `[r whistle-player]`를 두었고,
JS는 컴파일 결과 메타데이터에서 해당 노드 ID를 찾아 사용한다.
`n_0_*` 같은 컴파일러 생성 ID를 앱에 고정하지 않는다.
각 `[r]`의 메시지가 브라우저로 돌아오는 것을 확인하며, 별도로 PCM 출력도 측정한다.

`run()` 반환만으로 DSP가 준비됐다고 가정하지 않는다. `[loadbang]`에서 오는
`whistle-ready`를 받은 후에만 입력을 허용한다. 오디오는 클릭으로 시작하고,
시작 실패·종료 시 AudioContext와 노드를 정리한다. 재시작도 가능하다.
테스트 페이지가 숨겨지면 음소거하며 사용자가 해제한다. 마이크 입력은 사용하지 않는다.

## 실행

```sh
npm ci
npm run dev:audio
```

Vite에 표시된 주소 뒤에 `audio-lab/index.html`을 붙여 연다.
기본 주소는 `http://127.0.0.1:5173/whistle/audio-lab/index.html`이다.
`오디오 시작`을 클릭하고 두 입력 그룹을 조작한다. `오디오 종료`로 정지한다.

```sh
npm run test:audio
npm test
npm run build
```

오디오 테스트와 전체 브라우저 테스트, 빌드는 패치를 먼저 컴파일한다.
일반 `npm run dev`로 테스트 페이지를 사용할 때는 `npm run audio:build`를 먼저 실행한다.
패치를 수정한 뒤에도 다시 컴파일하고 페이지를 새로고침한다.
빌드 결과에도 `/whistle/audio-lab/index.html` 테스트 페이지가 포함된다.
생성 파일 `public/audio-test/`는 Git에서 제외하며 빌드로 재생성한다.

현재 실험 페이지는 직접 입력한 파라미터만 전송한다. 기존 게임 화면, 이동 로직,
기존 오디오 재생은 변경하지 않았다. 게임의 실제 클릭/보행과 연결하는 것은 다음 단계다.

## 검증 범위

Chromium에서 실제 WASM AudioWorklet 출력에 AnalyserNode를 연결해 확인한다.

- 편집: 겹침 0/1 메시지 수신, 약 440/660Hz 출력, 엔벌로프 종료 후 무음.
- 플레이: X/Y/Z·속도·재질값 수신, 약 220/770Hz 출력, 좌우 분리, 속도에 따른 크기 변화.
- 생명주기: 클릭 전 AudioContext 없음, 마이크 요청 없음, 음소거/해제, 속도 0의 무음,
  로드 실패 후 컨텍스트 정리·재시도, 종료 후 재시작.

자동 측정은 음원 생성과 전달 경로를 검증한다. 실제 스피커의 청감, 모바일 Safari,
게임과 동시에 재생할 때의 CPU·지연, 최종 샘플/외부 오브젝트 호환성은 별도 검증 대상이다.
