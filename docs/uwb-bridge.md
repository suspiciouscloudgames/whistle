# UWB 장비 연결

```text
USB의 AT+RANGE 또는 UDP의 거리 JSON
  → PC: 거리 검증 → 앵커 좌표로 위치 계산 → 태그별 평활화
  → WebSocket → UWB 페이지 → 기존 지면 판정·3D 표식·WebPd
```

PC 수신기는 최대 4개 태그를 각각 계산합니다. 페이지는 선택한 태그 1명의 위치와 소리를 표시합니다.
4명 동시 오디오 분리 출력·ESP32 스피커 전송은 이번 구현 범위에 포함하지 않습니다.
게임 편집기, 플레이어 이동, 지형 렌더링과 Pd 패치는 변경하지 않습니다.

## 장비 없이 실행

Node.js 22.13 이상에서 프로젝트 폴더를 열고 다음을 실행합니다.

```sh
npm ci
npm run dev
```

다른 터미널에서:

```sh
npm run uwb:demo
```

1. 개발 서버 주소의 `/whistle/uwb-lab/index.html`을 엽니다.
2. `샘플 세계` 또는 `Whistle 3D`를 선택합니다. Whistle 편집기와는 같은 브라우저·서버 주소를 사용합니다.
3. `위치 입력 방식`에서 `실제 데이터 · PC 수신기`를 선택합니다.
4. 수신기 주소 `ws://127.0.0.1:5194`, 태그 ID `0`으로 `연결 / 다시 연결`을 누릅니다.
5. 표식이 움직이면 `오디오 시작`을 누릅니다. 태그 ID `1`, `2`, `3`도 다시 연결해 비교할 수 있습니다.
6. 가상 장비 터미널을 `Ctrl+C`로 종료하면 표식과 소리가 멈춥니다.

가상 장비는 10Hz로 **앵커까지의 거리**를 만들어 실제 UDP 수신 경로에 보냅니다.
페이지에 완성된 좌표를 주입하는 방식이 아니므로 파싱·위치 계산·필터·전송을 함께 시험합니다.
기본 설정은 6×6m 공간, 보드 높이 1.2m 고정입니다. 표시되는 높이는 측정값이 아닌 **고정값**입니다.
기존 `가상 좌표 직접 입력` 모드는 그대로 사용할 수 있으며, 두 모드의 입력은 섞이지 않습니다.

## 앵커 설정

`config/uwb.example.json`을 복사해 실제 설치 위치로 수정하고 `--config`로 지정합니다.
모든 좌표·거리는 미터, `boardHeight`는 현실 바닥 기준 높이입니다.
`x`와 `z`가 바닥 평면이며, 가상공간에서의 플레이어 `y`와는 별개입니다.
`anchors[].boardHeight`는 앵커의 설치 높이입니다. 관객 보드의 높이는 `fixedHeight` 또는 3D 계산 결과를 사용합니다.

| 설정 | 의미 |
| --- | --- |
| `anchors` | 실제 앵커 ID와 X·Z·높이. 3~8개 |
| `tags` | 허용할 태그 ID. 문자열, 최대 4개 |
| `mode: "2d"` | 알려진 `fixedHeight`를 사용해 X·Z 계산. 평면에서 일직선이 아닌 앵커 3개 이상 |
| `mode: "3d"` | X·Z·보드 높이 계산. 같은 평면에 놓이지 않은 앵커 4개 이상 |
| `fixedHeight` | 2D 모드에서 실제 보드를 들 높이. 0~10m |
| `maxResidual` | 계산 위치와 측정 거리 사이 RMS 오차 허용치. 기본 0.35m |
| `smoothingMs` | 지수 평활화 시간 상수. 기본 120ms, 0이면 필터 끔 |

앵커의 높이 차이는 2D 계산에도 반영됩니다. 실제 보드 높이가 고정값과 달라지면 평면 위치에도 오차가 생깁니다.
3D 시험은 예제의 `mode`를 `"3d"`로 바꾸면 됩니다. 예제 앵커는 서로 다른 평면을 구성하며 가상 장비 높이도 움직입니다.
평활화는 태그별로 적용하며, 1초 수신 공백 또는 계산 실패 뒤에는 이전 위치를 끌고 오지 않습니다.
RMS가 작아도 앵커 설치 오차·반사파에 따른 공통 오차를 모두 감지하지는 못하므로 실제 위치와 비교해 보정해야 합니다.

UWB 페이지의 `전시장 매핑` 원점·회전·가로·세로는 이 현실 좌표를 가상 세계에 대응시키는 별도 설정입니다.
센서 좌표계와 매핑의 미터 기준을 맞추세요. 기본 설정끼리는 6×6m로 일치합니다.

## 실제 장비: USB부터 연결

```sh
npm run uwb:bridge -- --list-ports
npm run uwb:bridge -- --serial /dev/cu.usbmodemXXXX --config config/uwb.example.json
```

Windows에서는 경로 대신 `COM3`처럼 목록에 표시되는 포트를 사용합니다. 기본 속도는 115200이며 `--baud`로 변경할 수 있습니다.
Arduino Serial Monitor처럼 같은 포트를 열고 있는 프로그램은 종료합니다.
수신기는 보드를 읽기만 하며, 펌웨어 업로드·태그/앵커 역할 설정·AT 명령 전송을 대신하지 않습니다.
USB 연결이 끊기면 장비를 확인한 뒤 수신기를 다시 실행하고 페이지에서 다시 연결합니다.

기본 `--format makerfabs`는 MaUWB ESP32S3의 다음 원본 AT 보고를 지원합니다.

```text
AT+RANGE=tid:0,mask:07,seq:42,range:(150,200,350,0,0,0,0,0),rssi:(-70,-75,-80,0,0,0,0,0)
AT+RANGE=tid:0,mask:07,seq:43,range:(150,200,350,0,0,0,0,0),ancid:(3,1,2,-1,-1,-1,-1,-1)
```

위 숫자는 형식 예시입니다. 실제 앵커 설정과 일치하는 거리를 보내야 좌표가 계산됩니다.
`mask`의 유효한 항목만 사용하고 cm를 m로 바꿉니다. `ancid`가 있으면 배열 순서 대신 실제 앵커 ID를 사용합니다.
구형 보고처럼 `ancid`가 없으면 배열 0~7을 앵커 ID로 사용합니다. RSSI는 위치 계산에 사용하지 않습니다.
부팅 로그·OK 응답은 무시합니다. 한 줄이 완성될 때까지 기다리며 너무 긴 줄은 버립니다.
제조사의 `get_range` 예제가 변환한 `{"id":0,"range":[...]}` 형식은 지원하지 않습니다. 원본 AT 보고를 출력하는 태그 예제 또는 아래 표준 JSON을 사용합니다.

참고한 제조사 자료:
- [태그의 원본 UART 출력 예제](https://github.com/Makerfabs/MaUWB_ESP32S3-with-STM32-AT-Command/blob/main/example/esp32s3_at_t0/esp32s3_at_t0.ino)
- [AT 명령 매뉴얼 v1.1.2](https://github.com/Makerfabs/MaUWB_ESP32S3-with-STM32-AT-Command/blob/main/example/Firmware%20V1.1.6%20Manual%26%20Demo/Makerfabs%20UWB%20AT%20Module%20AT%20Command%20Manual(v1.1.2).pdf)

보유 장비의 정확한 펌웨어·USB 출력은 아직 실물 검증하지 않았습니다. 다른 형식이면 해당 로그에 맞는 어댑터가 필요합니다.

## Wi-Fi / UDP와 표준 JSON

USB로 먼저 확인한 뒤, ESP32 펌웨어에서 아래 패킷을 같은 네트워크의 PC IP:5195로 보내면 됩니다.
PC가 외부 UDP를 받게 하려면 명시적으로 실행합니다.

```sh
npm run uwb:bridge -- --udp-host 0.0.0.0 --config config/uwb.example.json
```

UDP 한 데이터그램에 하나의 UTF-8 JSON 객체를 보냅니다. 최대 4096바이트입니다.
USB로 같은 형식을 보낼 때는 `--serial PORT --format json`을 쓰고 객체마다 줄바꿈합니다.

```json
{
  "type": "ranges",
  "tagId": "0",
  "seq": 42,
  "ranges": [
    { "anchorId": "0", "distance": 3.419064199455752 },
    { "anchorId": "1", "distance": 5.974110812497538 },
    { "anchorId": "2", "distance": 5.974110812497538 },
    { "anchorId": "3", "distance": 3.2388269481403297 }
  ]
}
```

거리값은 한 측정 주기의 동일 태그 거리 묶음이어야 합니다. 서로 다른 시점의 오래된 거리를 합치지 마세요.
ID는 문자열, `seq`는 태그별로 증가하는 0 이상의 정수입니다. 활성 추적 중 중복·역순 패킷은 무시합니다.
장비가 재시작해 카운터가 초기화되면 1초 수신 공백 뒤 새 시퀀스를 받아들입니다.
Makerfabs 원본 USB 보고는 직렬 순서를 사용하므로 카운터 순환을 허용하고 연속 중복은 무시합니다.
센서 타임스탬프의 절대 시각은 사용하지 않고 PC 도착 시각으로 관리합니다.
서로 다른 송신기가 동일 태그를 동시에 보내지 않도록 구성합니다.

WebSocket은 PC의 `127.0.0.1:5194`에서만 열리므로 페이지도 같은 PC의 localhost 개발 서버에서 사용합니다.
공개 배포 페이지의 원격 접속은 지원하지 않습니다. UDP 기본 바인딩도 localhost이며 외부 장비 연결 시에만 변경합니다.
포트 충돌은 `--ws-port`, `--udp-port`로 변경하고 페이지의 수신기 주소도 맞춥니다.

## 수신 중단과 사운드

페이지는 선택한 태그의 신규 좌표만 사용합니다. 1초 이상 새 좌표가 없거나 연결 종료·계산 실패가 발생하면 표식을 없애고 음소거합니다.
정상 데이터가 돌아오면 이미 켜 둔 오디오만 재개합니다. `오디오 종료` 뒤에는 데이터가 도착해도 시작하지 않습니다.
새 연결에 과거 좌표를 재전송하지 않습니다. 연결 실패는 주소·PC 프로그램을 확인하고 `다시 연결`합니다.
직접 입력 모드에는 시간 초과 판정이 없습니다.

보드 높이는 기존 `whistle-board-height`에 별도로 전달합니다.
3D 표식은 계속 가상 지면에 놓이며 플레이어 높이·이동·지형에는 영향을 주지 않습니다.

## 검사

```sh
npm run test:uwb
npm test
npm run build
```

검사에는 거리 계산·퇴화한 앵커 배치·단위 변환·시퀀스·USB 모의 직렬 포트·실제 UDP/WebSocket·4개 가상 태그가 포함됩니다.
브라우저에서는 좌표·보드 높이의 Pd 전달, 태그 선택, 입력 전환, 잘못된 거리·수신 공백·연결 종료 시 음소거와 기존 세계 보존을 확인합니다.
