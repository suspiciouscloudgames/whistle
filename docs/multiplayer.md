# 멀티플레이 최소 구현

`multiplaytest`의 첫 구현. 같은 방의 세계 문서를 함께 편집하며, 각자 그 세계를 탐험한다.
사용자 구분은 **현재 커서 칸 + 편집한 칸의 일시 강조**다. 칸의 영구 소유권을 만들지 않는다.

## 실행과 확인

Node 22.13 이상에서 `npm ci`, `npm run dev`를 실행한다. 화면의 **함께 만들기 → 방 링크 복사**로 초대한다.
동일 URL을 다른 브라우저나 시크릿 창에 열면 별도 참여자가 된다. 최대 8명이다.

### 한 PC의 두 창에서 소리 테스트

1. 한 창에서 방을 만들고 같은 방 링크를 다른 창에 연다.
2. **두 창 모두** 상단의 **로컬 테스트: 백그라운드 소리 유지**를 체크한다.
3. 각 창에서 플레이를 눌러 오디오를 시작한다. 두 창을 나란히 놓고 번갈아 이동·회전한다.
4. 필요하면 한 창의 **다른 사람의 소리** 슬라이더로 원격 음량을 조절한다.

이 옵션은 `localhost`, `127.0.0.1`, `[::1]`에서만 나타나며 기본값은 꺼짐이다.
설정은 창/탭의 sessionStorage에 저장하여 새로고침에도 유지한다. 방 링크에는 포함하지 않는다.
켜면 3D에서 blur/탭 숨김에도 활성 상태와 오디오를 유지하고,
화면 갱신이 멈춰도 마지막 계산 위치를 1초 간격으로 재전송한다.
위치의 문서 revision도 보존하므로, 숨겨진 동안 세계가 바뀌면 새 렌더 프레임이 계산될 때까지
오래된 위치를 새 세계의 값으로 제출하지 않는다.
창 전환 시 눌린 이동 키는 계속 해제해 자동으로 걸어가는 일을 방지한다.
옵션을 끄면 기존 자리 비움/음소거 동작으로 돌아간다. 2D 복귀·방 나가기·연결 종료의 음원 정리는 그대로 적용된다.
브라우저나 OS가 탭을 강제로 정지시키는 절전 기능까지 해제하지는 않으므로 테스트 창을 열어 둔다.

옵션 검증: 두 브라우저 컨텍스트에서 blur 이벤트와 렌더 프레임 중지를 적용한 뒤 6.5초 동안
1초 간격 위치 전송, 양쪽 원격 PCM 출력을 확인했다. 옵션 해제 후 blur와 2D 복귀에서는
원격 출력이 0이 됐고, 다시 켜면 재생됐다. 옵션 전환 중 AudioContext는 재생성되지 않았으며
새로고침 후 설정이 유지됐다. 기존 편집·데스크톱/모바일·오디오 회귀 테스트 7개와 빌드도 통과했다.

빌드한 앱과 방 서버를 함께 실행하려면:

```sh
npm run build
npm start
# 다른 장치에서 접속할 서버 바인딩이 필요하면:
HOST=0.0.0.0 PORT=5173 npm start
```

주소는 `/whistle/`이며 WebSocket도 같은 호스트의 `/whistle/room-socket`을 사용한다.
다른 장치에는 localhost 대신 서버 주소를 전달한다. **AudioWorklet은 보안 컨텍스트가 필요하므로
다른 장치의 소리 테스트에는 신뢰할 수 있는 HTTPS/WSS 주소를 사용한다.** localhost 테스트는 HTTP로 가능하다.
리버스 프록시는 WebSocket 업그레이드와 원래 Host를 전달해야 한다.
`npm run dev:lan`은 개발 서버를 LAN에 바인딩하는 명령일 뿐 HTTPS를 제공하지 않는다.
GitHub Pages 같은 정적 호스팅만으로는 방 서버가 실행되지 않는다. 이번 작업에는 배포가 포함되지 않는다.

## 2D 규칙

- 접속 중인 사람마다 중복되지 않는 색과 번호를 부여한다. 현재 칸을 반투명하게 채우고 테두리와 번호를 표시한다.
- 키보드 포커스도 현재 칸이다. 격자 밖, 자리 비움, 3D 전환, 퇴장 시 현재 칸 표시를 지운다.
- 확정된 편집 칸은 작성자의 색으로 900ms 강조한다. 원래 재질·높이·기호는 유지한다.
- **내가 실제 변경한 칸의 편집음만** 내 브라우저에서 재생한다. 다른 사람의 편집, 실행 취소, 방 초기 로딩은 편집음을 내지 않는다.
- 서버가 변경 순서를 정하고 revision과 변경 필드만 배포한다. 서버 확정 후 화면에 반영하며 낙관적 편집은 아직 없다.
- 높이 올리기/내리기는 서버의 현재 높이에 증감한다. 같은 스트로크에서 같은 칸은 한 번만 적용한다.
- 재질과 구멍 여부는 한 필드, 높이는 별도 필드다. 따라서 높이와 재질의 동시 수정은 모두 반영된다.
- 같은 칸의 재질 칠하기는 서버 도착 순서의 마지막 결과가 남는다. 구멍은 토글 대신 명시적인 열기/메우기 명령이다.
- 한 칸에는 기호 하나만 둔다. 동시에 추가하면 먼저 확정된 기호를 유지하고, 삭제는 사용자가 본 기호 ID가 일치할 때만 허용한다.
- 기호 속성·사용자 이미지·날씨·시작점 변경은 이전 값이 아직 같은지 검사한다. 오래된 편집이 새 값을 덮어쓰면 건너뛴다.
- 실행 취소는 사용자별 최근 40개 작업, 드래그는 한 작업이다. 필드별 변경 이력을 확인해 다른 사람이 이후 수정한 필드는 보존한다.
  다시 실행도 같은 검사를 한다. 일부만 취소되는 경우 안내한다. 새로 접속하면 개인 실행 취소 이력은 초기화된다.
- 함께 만드는 동안 전체 세계 불러오기·다시 시작·지형 재추첨은 제한한다. 파일 내보내기는 가능하다.

## 3D 사운드 최소 규칙

개인이 듣는 상호작용 소리는 별도 **`audio/patches/multiplayer-interaction.pd`**가 담당한다.
나를 포함한 활성 3D 인원이 **1명일 때 단음 → 2명일 때 2음 화음 → 3명일 때 3화음 → 4명 이상일 때 리듬 화음**으로 바뀐다.
4명 모드에서는 가장 가까운 상대가 가까울수록 리듬이 빨라져 각자의 위치가 개인의 소리에 영향을 준다.
방 안에서는 이 패치가 기존 자기 지속음을 대신하며, 아래 상대별 위치음은 함께 유지한다.
[상세 사운드 디자인과 패치 수정 방법](../audio/multiplayer-interaction.md)을 참고한다.

| 항목 | 첫 구현의 규칙 |
| --- | --- |
| 보이는 것 | 다른 플레이어의 아바타는 표시하지 않는다. 접속 목록에 색·번호·2D/3D 상태만 표시한다. |
| 들리는 대상 | 나와 상대가 모두 3D에 있고 활성 상태일 때 상대의 연속 시험음을 듣는다. 2D 편집자는 원격 음원이 아니다. |
| 전달하는 것 | 오디오 파일/마이크 스트림 대신 위치, 발 높이, 방향, 풀·거친 바닥·물, 접지·낙하 상태를 약 80ms마다 전달한다. |
| 합성 | 각 수신자가 동일한 `remote-player.pd`를 실행한다. 정지해 있어도 소리는 지속하며 이동 속도에 비례해 키우지 않는다. |
| 시험 음색 | `220 + 220 × 정규화된 z + 220 × 풀 + 440 × 거친 바닥 + 110 × 물` Hz의 사인파, 원본 진폭 0.02. 최종 사운드 디자인은 별도다. |
| 위치 | 한 칸 = 장면 2단위. 음원은 상대의 발 높이 +0.7, 청취자는 내 카메라 눈높이와 시선 방향이다. |
| 공간화 | Pd 출력을 모노로 합친 후 HRTF Panner로 좌우·방향을 계산한다. 정면 고정 패닝이 아니다. |
| 거리 | inverse 감쇠, 기준 거리 2단위(한 칸), rolloff 1, 최대 거리 파라미터 100. 급격한 가청 거리 컷은 없다. |
| 보간 | 위치는 약 80ms, 음량은 약 60ms의 시정수로 부드럽게 변경한다. 순간이동 예측은 하지 않는다. |
| 여러 음원 | 최대 다른 사람 7명. 각 소스 음량을 `1/√음원 수`로 줄이며 별도 원격 음량 슬라이더를 제공한다(기본 65%). |
| 중지 | 상대가 2D로 돌아가거나 자리 비움·퇴장하면 페이드 후 제거한다. 위치 업데이트가 3초 이상 없으면 서버가 음원을 해제한다(1초 간격 검사). |
| 내 일시정지 | 기본적으로 blur/숨겨진 탭에서는 듣기와 위치 전송을 중지한다. 다시 키나 포인터를 조작하면 재개한다. 로컬 테스트 옵션을 켠 3D 창은 예외다. |

하나의 AudioContext를 공유하고 기본 소리, 개인의 상호작용 패치, 상대별 위치음 Pd 세션을 구분한다.
상대가 사라져도 공유 AudioContext를 닫지 않는다. 나 자신의 위치 패킷은 재합성하지 않아 자기 소리가 중복되지 않는다.
차폐·잔향·도플러·음성 채팅·발걸음 이벤트·충돌 이벤트 공유는 이번 최소 구현에 없다.
벽 너머 소리도 거리와 방향에 따라서 들린다.

## 탐험 중 편집 반영

확정된 문서 변경을 다음 렌더 프레임에서 지형·환경·충돌·음향 재질 계산에 사용한다.
전체 Scene을 다시 시작하지 않고 현재 위치와 시선을 유지한다. 바뀌지 않은 기호의 로컬 시뮬레이션 상태도 보존한다.
현재 위치에 장애물이 생성되면 가까운 유효한 칸 중심으로 이동한다. 발밑 바닥이 없어지면 기존 낙하/시작점 복귀 동작을 따른다.
시작점에는 구멍이나 단단한 기호를 만들 수 없다.

공유 범위는 세계 문서와 플레이어 음원 상태다. 기존 규칙에 의한 기호의 이동·사라짐 등 런타임 시뮬레이션은 각자 실행하므로
모든 탐험자의 런타임 상태가 동일하다는 보장은 아직 없다. 같은 문서 revision의 플레이어 프레임만 서버가 수락하지만,
환경 값과 이동의 물리적 정합성은 아직 서버에서 재계산하지 않는다.

## 방 수명과 제한

- 로그인 없는 링크 기반 실험이다. 링크를 가진 사람은 누구나 편집할 수 있다.
- 방은 단일 Node 프로세스 메모리에만 저장한다. 서버 재시작 또는 마지막 퇴장 후 30분이 지나면 사라진다.
- 연결이 끊기면 편집을 막고 다시 연결/방 나가기를 제공한다. 오프라인 편집 큐와 자동 재접속 병합은 없다.
- 기존 개인 localStorage 저장은 방 안에서 중단하고 방 밖으로 나오면 개인 세계를 다시 불러온다.
  방에서 만든 결과는 **공유 → 파일 저장**으로 보관한다. 방을 떠날 때 개인 세계에 자동 덮어쓰지 않는다.
- 서버는 유효성 검사, 칸 중복·시작점 보호, 메시지 크기/빈도 제한, 느린 연결 정리, heartbeat를 적용한다.
  영속 저장, 인증, 방 관리 권한, 다중 서버 확장, 대규모 부하 검증은 후속 범위다.

## 참고한 설계 방향

- [Tilemap Town](https://github.com/NovaSquirrel/TilemapTown): 브라우저에서 여러 사람이 타일 세계를 만들고 탐험하는 구조.
  Whistle은 편집 커서만 시각화하고 탐험자의 존재는 소리로 표현한다.
- [r/place 기술 기록](https://redditinc.com/news/how-we-built-rplace): 변경 단위를 전달해 공유 격자의 상태를 맞추는 방향.
  여기서는 대규모 캔버스의 제약을 그대로 가져오지 않고 작은 방의 서버 순서를 사용한다.
- [Figma의 멀티플레이 기술 기록](https://www.figma.com/blog/how-figmas-multiplayer-technology-works/): 속성별 충돌 처리의 참고.
  Whistle은 높이/바닥/기호를 구분하고 사용자별 조건부 실행 취소를 사용한다.
- [Web Audio PannerNode 사양](https://www.w3.org/TR/webaudio-1.0/#PannerNode): 청취자와 음원 좌표, HRTF, 거리 감쇠의 구현 기준.

## 검증

`npm run test:unit`에 충돌, 중복 명령, 스트로크 단위 취소, 부분 취소/재실행, 실제 두 WebSocket 접속 테스트가 포함된다.
`npm run test:browser`는 기존 편집·저장·모바일·3D·Pd 회귀 테스트를 실행한다.
별도 두 Chromium 세션에서 커서 색, 공유 칠하기, 개인 취소, 2D 원격 음소거와 3D 실제 PCM 출력을 검사한다.
원격 Pd의 한쪽 채널만 연결되는 문제는 Panner 입력을 명시적 모노로 설정해 해결했다.

2026-11-16 확인: 단위·서버 테스트 100개, 기존 브라우저 테스트 31개, 프로덕션 빌드 통과.
두 Chromium 세션에서 다른 사람의 2D 편집은 수신자의 AudioContext를 생성하지 않았고,
3D 진입 시 원격 PCM이 출력됐다. 청취자 방향을 반대로 돌리면 좌/우 RMS 우세가 반전됐으며,
상대가 2D로 복귀하면 원격 RMS는 양쪽 모두 0이 됐다. 탐험 중 발밑 높이 편집은
위치 X/Z와 yaw를 유지한 채 발 높이에 반영됐다. 실제 헤드폰 청감과 여러 실기기의 네트워크 지연 평가는 후속 확인이다.
