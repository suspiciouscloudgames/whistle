# 편집 중 지형 생성 비용 비교

2026-11-11, Apple M5 Pro / macOS arm64 / Node 22.17.1 / Playwright 1.65.0 Chromium.
저장본 보호 수정이 반영된 상태에서 이번 최적화 적용 직전·직후를 비교했다.

## 측정 방법

`npm run benchmark:editor -- before`와 `npm run benchmark:editor -- after`로
각각 독립 브라우저 페이지에서 3회 반복했다. 12×12 지도, 시드 4831,
동일한 풀·나무·물·돌 배치와 동일한 마우스 입력을 사용했다.

Playwright가 모듈 응답에 측정 코드를 삽입한다. 앱 소스에는 측정 코드를
추가하지 않았다. 소프트웨어 그래픽 처리의 영향을 분리하기 위해 측정 중에만
`renderer.render` 호출을 생략했다. 따라서 아래 시간은 지형 생성 함수의
누적 CPU 시간이며, GPU 비용·FPS·전체 입력 지연을 뜻하지 않는다.
시간은 3회 중앙값이다. 호출 횟수는 3회 모두 동일했다.

| 작업 | 지형 생성 횟수 전 → 후 | 지형 생성 CPU 시간 전 → 후 | 환경 계산 횟수 전 → 후 |
|---|---:|---:|---:|
| 초기 화면 | 2 → 1 | 257.2 → 140.4 ms | 4 → 2 |
| 같은 재질의 한 칸에서 드래그 입력 8회 | 0 → 0 | 0 → 0 ms | 24 → 0 |
| 구조물을 만들지 않는 기호 6개 배치 | 6 → 0 | 657.7 → 0 ms | 24 → 0 |
| 서로 다른 칸의 높이 변경 6회 | 6 → 6 | 638.5 → 674.5 ms | 24 → 6 |

초기 지형 생성 CPU 시간은 약 45% 감소했다. 관계없는 기호 배치의 지형
재생성과 같은 칸 반복 입력의 환경 재계산은 제거됐다. 실제 높이 편집에서는
환경 계산이 75% 줄었지만, 전체 메시 생성은 여전히 필요하다. 이 작업의 지형
생성 시간은 이번 측정에서 약 5.6% 증가했으며, 속도 개선을 확인하지 못했다.
메시 생성 알고리즘과 갱신 주기는 이번 변경 범위에 포함하지 않았다.

원시 결과는 로컬 `output/performance/before.json`, `output/performance/after.json`에
저장되어 있다. 다시 측정할 때는 다른 테스트와 벤치마크를 동시에 실행하지 않는다.

## 결과 유지 검증

- 최적화 전 생성한 평지·자연환경·구조물·24×24 지도 4종의 기준값과 비교한다.
- 정점 속성, 인덱스, 오브젝트 변환, 인스턴스 행렬·색상, 재질 설정, 셰이더 코드,
  텍스처 픽셀의 SHA-256 값이 일치해야 한다.
- 캐시를 사용한 환경·구조물·배치 피드백을 원래 계산 결과와 비교한다.
- 구조물이 있는 지도 전체의 보행 높이를 0.25칸 간격으로 비교한다.
- 브라우저에서 초기 생성 횟수, 무효 편집, 일반 기호 배치, 다리 생성·제거,
  실행 취소·다시 실행을 검증한다. 이 테스트에서는 GPU 렌더링을 생략하지 않는다.

검증 결과: 단위 테스트 87개, 브라우저 테스트 18개 모두 통과.
TypeScript 검사와 프로덕션 빌드도 통과했다. 기존 3D 청크 크기 경고는 남아 있다.
